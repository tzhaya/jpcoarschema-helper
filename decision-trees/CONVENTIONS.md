# フローチャート共通規約

`decision-trees/` 配下の各プロパティ入力ガイドが共通で従う規約です。各ページはこのファイルを参照し、ここで定義した凡例・用語・方針を重複定義せずに使います。

---

## 1. ページ構成

各プロパティのページは次の順で構成します。

1. **見出し・対象**（対象プロパティ、典拠リファレンスへのリンク）
2. **この項目の性質**（4観点の早見表 → 第8節）
3. **まず入力するもの**（代表的な入力先の早見表）
4. **記号凡例**（→ 本ファイルへのリンクで代替可）
5. **入力フローチャート**（Mermaid `flowchart TD`）
6. **入力プロセス対応表**（判断・質問・回答・アクション・要素／属性・入力例）
7. **使い分けの目安**（迷いやすいケース）
8. **入力例**（XML）
9. **注記（入力ルール）**
10. **参考**（公式ページ・[要素別ルール](../reference/)・[DOI対照表](../reference/JPCOAR_JaLC_Crossref_requirements.md)）

---

## 2. 記号凡例（Mermaid）

| 記号 | 意味 |
|------|------|
| 楕円 `([ ])` | 開始 / 終了 |
| ひし形 `{ }` | 判断（Yes / No や種類の分岐） |
| 長方形 `[ ]` | 処理（入力・設定する内容） |
| 平行四辺形 `[/ /]` | 入力・情報源 |

---

## 3. 公式記号と入力作業での読み替え（スキーマ層）

JPCOARスキーマの公式記号は正確さのために残しつつ、各入力ガイドでは入力者が作業として理解しやすい言い換えを併記します。

| 記号 | 厳密な意味 | 入力時の言い換え | 注意 |
|------|------------|------------------|------|
| M | 必須（Mandatory） | 必ず記載 | 省略できません |
| MA | 該当する場合は必須（Mandatory if Applicable） | 条件に当てはまる場合は記載 | 何が条件かを本文で具体的に示します |
| R | 推奨（Recommended） | できれば記載 | 省略は可能ですが、記載が望ましい項目です |
| 1-N | 1回以上、繰返可 | 1つ以上記載、複数可 | 少なくとも1つ必要です |
| 0-N | 0回以上、繰返可（必須以外） | あれば記載、繰り返し可 | ない場合は省略できます |
| 0-1 | 0〜1回、繰返不可（必須以外） | あれば1つだけ記載 | 複数は記載できません |

---

## 4. DOI要件の用語（DOI登録層）

[JPCOAR/JaLC対照表](../reference/JPCOAR_JaLC_Crossref_requirements.md) の語を次の意味で用います。混同しないこと。

| 用語 | 意味 |
|------|------|
| **必須** | 必ず入力が必要 |
| **条件付必須** | 特定条件下で必須（例: 親要素がある場合） |
| **任意** | 入力は任意（0以上 または 0〜1） |
| **推奨** | 任意だが入力が推奨される |

> 注意: 対照表では項目ごとに「任意」と「推奨」を使い分けています（例: タイトルの `xml:lang` は JaLC で**任意**、作成者名の `xml:lang` は JaLC で**推奨**）。安易に言い換えないこと。
> 入力ガイドで補足する場合も、DOI登録層の正式語（必須 / 条件付必須 / 任意 / 推奨）は置き換えず、「任意（あれば記載）」のように括弧で作業上の意味を添えます。

---

## 5. 3層の原則（最重要）

各要素・属性の要件は、必ず次の3層を区別して記述します。混同が誤りの主因です。

| 層 | 典拠 | 例 |
|----|------|----|
| **スキーマ層** | [公式説明ページ](https://schema.irdb.nii.ac.jp/ja/schema) / [要素別ルール](../reference/) | `dc:title` は M（必須・1-N）、`xml:lang` は MA |
| **DOI登録層** | [対照表](../reference/JPCOAR_JaLC_Crossref_requirements.md) | タイトル `xml:lang` は JaLC＝任意 / Crossref＝必須 |
| **本ガイド運用方針** | 本ファイル | `xml:lang` は入力漏れ防止のため原則付与 |

---

## 6. `xml:lang` の運用方針

- スキーマ上は「該当する場合は必須（MA）」。
- DOI登録要件は要素・登録先ごとに異なる（対照表に従う）。一般傾向として **JaLC は任意〜推奨、Crossref は必須**、Crossref の一部要素は **`xml:lang="en"` 必須**。
- **本ガイドの方針**: 入力漏れと多言語混在を防ぐため、**原則としてすべての言語依存値に付与**する。
- **1言語＝1要素**: 1つの要素に複数言語を並べない。言語が異なる場合は要素を分ける（並列表記は非推奨）。

### 言語コード

| 用途 | コード例 |
|------|---------|
| 日本語 / 英語 / 中国語(簡体) | `ja` / `en` / `zh-cn` |
| 片仮名ヨミ | `ja-Kana` |
| ローマ字ヨミ | `ja-Latn` |

- ヨミ（`ja-Kana` / `ja-Latn`）を入れる場合は、必ず本文言語（通常 `ja`）の値も併記する。

---

## 7. 用語

| 用語 | 定義 |
|------|------|
| 並列タイトル | 同一資源の代表タイトルが複数言語で示されたもの。`dc:title` を言語別に繰り返す |
| その他のタイトル | 本タイトル以外（副題・目次・奥付タイトル等）。`dcterms:alternative` |
| ヨミ | 読みの情報。`ja-Kana` / `ja-Latn` |

> 用語はプロパティ追加に応じて追記します。**公式に存在しない概念を独自に追加しない**こと（追加する場合は「運用上の区分」と明記）。

---

## 8. 項目の性質（評価の物差し）

各ページの冒頭（見出し・対象の直後）に「**この項目の性質**」として、入力作業の性質を4観点の表で示します。入力者が「この項目はどれだけ慎重に判断すべきか」を作業前に把握できるようにするためです。

| 観点 | 問い | 記載する値 |
|------|------|-----------|
| **入力の型** | 何を行う作業か | **解釈型**（資料の性質を解釈して統制語彙等から選ぶ）／**転記型**（書誌・資料からの転記が中心）／**調査型**（外部情報源を調べて値を得る）。複合する場合は「転記型＋調査型」のように併記し、どの部分がどの型かを一言添える |
| **他項目への影響** | この項目の選択が他項目の必須度・値を変えるか | **あり**（波及先の項目を明記）／**なし**。他項目から影響を**受ける**側の場合もここに記す |
| **事前調査** | 入力前に外部を調べる必要があるか | **必要**（情報源・ツールを明記）／**不要** |
| **誤入力の影響** | 間違えると何が起きるか | 具体的な実害を書く（例: DOI登録エラー、公開ポリシー・著作権違反、検索・発見性の低下、著者・資源の同定不能） |

### 記入フォーマット

```markdown
## この項目の性質

| 観点 | 評価 |
|------|------|
| 入力の型 | 解釈型 — dateType 9種から資料の状況に合う種類を選ぶ |
| 他項目への影響 | あり — DOI登録の代表日付の選定に波及 |
| 事前調査 | 不要 — 奥付・書誌情報から判断できる |
| 誤入力の影響 | DOI メタデータの発行年誤表示、版の同定の混乱 |
```

### 運用

- **解釈型**の項目ほどフローチャートの分岐を丁寧にたどる価値があります。**転記型**は対応表の確認だけで足りることが多く、**調査型**は情報源への導線（検索ツール・データベース）を「参考」節に必ず置きます。
- この4観点は [ROADMAP](../ROADMAP.md) の優先度判断（判断負荷の重い解釈型を優先）にも使用しています。
- 評価はあくまで**運用上の目安**（第5節の3層でいう本ガイド運用方針の層）であり、公式スキーマの規定ではありません。
