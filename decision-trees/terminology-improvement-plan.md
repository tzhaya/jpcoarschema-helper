# 初学者向け用語改善プラン

## Summary

- `CONVENTIONS.md` に「公式記号」と「入力作業での言い換え」を併記し、初学者は自然文で理解できるようにする。
- 各入力ガイドは利用者向け本文をやさしい表現に寄せつつ、JPCOAR公式・DOI対照表の用語は失わない。
- `0-N` は、入力ガイド本文では **「あれば記載、繰り返し可」** と言い換えてよい。ただし凡例・公式準拠箇所では `0-N` と厳密な意味も併記する。

## Key Changes

- `decision-trees/CONVENTIONS.md`
  - 第3節を「公式記号と入力作業での読み替え」に改める。
  - `記号 / 厳密な意味 / 入力時の言い換え / 注意` の表にする。
  - DOI登録層の「必須 / 条件付必須 / 任意 / 推奨」は対照表の正式語なので置換せず、必要に応じて括弧で作業上の意味を補足する。

- `decision-trees/*.md`
  - 冒頭・「まず入力するもの」・注記は、入力者が実際に行う作業が分かる文にする。
  - `M` は「必ず記載」、`MA` は「条件に当てはまる場合は記載」、`R` は「できれば記載」と補足する。
  - `1-N` は「1つ以上記載、複数可」、`0-N` は「あれば記載、繰り返し可」、`0-1` は「あれば1つだけ記載」と補足する。
  - Mermaid と対応表では短いラベルを使い、必要な場所だけ公式記号を括弧で残す。
  - XML例・要素名・属性名・DOI要件そのものは変更しない。

## Test Plan

- `rg` で `0-N|0-1|1-N|MA|必須以外|該当する場合` を確認し、利用者向け本文に硬い表現が残りすぎていないか見る。
- 各入力ガイド内で、スキーマ層・DOI登録層・本ガイド運用方針が混ざっていないことを確認する。
- `reference/*_rules.md` と `JPCOAR_JaLC_Crossref_requirements.md` に照合し、必須度・繰返回数・属性要件・DOI要件が変わっていないことを確認する。
- Mermaid の構文と Markdown 表・コードフェンスの崩れがないことを目視確認する。

## Assumptions

- 公式準拠の記録である `reference/*_rules.md` は変更しない。
- 初学者向けの言い換えは `decision-trees/` の入力ガイド側に入れ、公式記号は凡例・括弧書きで保持する。
- 「あれば記載、繰り返し可」は `0-N` の利用者向け表現として採用するが、`MA` のような条件付き必須には単独で使わず、条件を明示する。
